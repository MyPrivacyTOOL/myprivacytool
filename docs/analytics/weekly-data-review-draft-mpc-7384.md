## Weekly data review

**Read**
- The latest row of the weekly tracker (Notion page `9cffd646cda9456e9974167b29d750ba`, data source `49361779-2050-4d96-8f69-ad1da1636810`) where `Week Of` is set.
- The last 7 rows of the daily database (Notion page `7d0b2fa362fa4a10bce866c51e7b76ee`, data source `5bf43eae-1da1-438e-859d-56b241b5b1ac`).
- Read `Agent Insights` for the source of each number.
- If either is unreadable, say so in the session output and in the decision digest.

**Quote** (exact property names; `Conversion Rate` and `Conversion Rate %` are different columns)
- Cumulative Scans, Weekly New Scans, Target Cumulative Scans, Pace Gap %, Pace Status, Blog Posts Published, X Threads Posted, GA4 Active Users, Current MRR, and the daily date range covered.
- A blank is reported as "blank", never as zero.

**Respond**
- Pace Status 🔴 Behind: create 1 to 3 dated tasks aimed at the weakest funnel stage (traffic, scan start, scan completion, lead capture). Name the stage and the reason in `Agent Insights`.
- Fewer than 3 blog posts or fewer than 7 X threads in the week: create publishing tasks for the shortfall.
- A source blank for 2 days running: create a collector-fix task and flag it in the digest.
- Any number moved by more than half week on week: note the likely cause, or create a task to find it.
- These count toward the session's 1 to 3 tasks. The anti-idle rule still applies.

**Must not**
- Change the ladder or any target. An unreachable target goes to Chris through the decision digest.
- Edit past rows. Add a dated correction instead.
- Fill a blank with an estimate.
- Report a write without fetching it back.

**Ownership**
- MyPrivacyToolAnalyticsClaw owns the weekly review. Marketing acts on traffic and content findings, Sales on conversion, Finance on MRR.
