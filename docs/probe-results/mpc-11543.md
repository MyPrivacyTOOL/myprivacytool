## Telegram (0 found, 2 failed, 6 not run)
No computer could act as the test account from this cloud session, so the Telegram part was tried by hand by the owner in the
@MyPrivacyTOOL_Bot chat only. No passcode, password or token was entered by this session and nothing outside the bot chat was used.
The owner closed the batch at 13 of 21 (2026-11-27) and the 8 Telegram ids are carried into batch 2.

**Finding for the two event ids (from the code, not a live webhook query):** `scripts/ci/telegram-webhook-register.mjs` registers the webhook with
`allowed_updates: ["message", "callback_query"]`. Edits arrive as `edited_message` and block/unblock as `my_chat_member`, which the bot
therefore never receives, so `tg.edits` and `tg.blocked_bot` cannot return their field on the live bot as configured. The owner's attempt
(an edit and a block attempt in the bot chat) produced no event reply, which is consistent with this. Allowing those updates means re-registering the
webhook, a production action that is not part of this task.
