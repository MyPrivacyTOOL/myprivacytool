# Core Brain Worker — Deployment & Integration Guide\n\n**Status:** Ready for deployment (MPC-8601)\n**Deployment Timeline:** 2–3 hours for full setup\n**Prerequisites:** Cloudflare account, Supabase project, Qwen API access\n\n## Quick Start\n\n### 1. Clone the branch and navigate\n\n```bash\ngit checkout feat/mpc-8601-core-brain\ncd workers/core-brain\n```\n\n### 2. Install Wrangler and dependencies\n\n```bash\nnpm install\nnpm install -g wrangler  # Install Cloudflare CLI\n```\n\n### 3. Create Cloudflare KV namespace\n\n```bash\nwrangler kv:namespace create \"CORE_BRAIN_KV\"\nwrangler kv:namespace create \"CORE_BRAIN_KV\" --preview\n```\n\nNote the namespace IDs and update `wrangler.toml`:\n\n```toml\n[[kv_namespaces]]\nbinding = \"CORE_BRAIN_KV\"\nid = \"<PRODUCTION_ID>\"\npreview_id = \"<PREVIEW_ID>\"\n```\n\n### 4. Set environment variables in Cloudflare Dashboard\n\nNavigate to **Cloudflare Dashboard → Workers** → Click on **mpt-core-brain** → **Settings** → **Variables**\n\nAdd these variables:\n\n| Variable | Example | Notes |\n|----------|---------|-------|\n| `SUPABASE_URL` | `https://project.supabase.co` | From Supabase Settings |\n| `SUPABASE_SERVICE_KEY` | `eyJhbGc...` | Service role key (NOT anon) |\n| `QWEN_API_KEY` | `sk-...` | Alibaba Cloud API key |\n| `QWEN_MODEL` | `qwen-turbo` | Model name |\n| `WEBHOOK_SECRET` | `super-secret-123` | Your choice — share with webhook sources |\n| `X_API_KEY` | (optional) | X/Twitter Bearer token |\n| `TELEGRAM_BOT_TOKEN` | (optional) | Telegram bot token |\n| `MIRROR_AND_RISK_WORKER_URL` | `https://mpt-mirror-risk...` | URL to MPC-8302 Worker |\n\n**⚠️ CRITICAL:** Use the Cloudflare Dashboard UI to set these — DO NOT commit to git.\n\n### 5. Deploy the Worker\n\n```bash\nwrangler deploy\n```\n\nOutput will show your Worker URL:\n```\nDeployed to https://mpt-core-brain.your-account.workers.dev\n```\n\n### 6. Verify deployment\n\n```bash\ncurl https://mpt-core-brain.your-account.workers.dev/\n```\n\nExpected response:\n```json\n{\"status\":\"Core Brain operational\"}\n```\n\n## Supabase Setup\n\n### Create Required Tables\n\nRun these in your Supabase SQL editor:\n\n```sql\n-- 1. User state tracking\nCREATE TABLE user_state (\n  sender_id TEXT PRIMARY KEY,\n  platform TEXT NOT NULL,\n  language_code TEXT DEFAULT 'en',\n  opted_in BOOLEAN DEFAULT true,\n  created_at TIMESTAMP DEFAULT now(),\n  updated_at TIMESTAMP DEFAULT now()\n);\n\n-- 2. Interaction log (for analytics)\nCREATE TABLE interaction_log (\n  id BIGSERIAL PRIMARY KEY,\n  sender_id TEXT NOT NULL,\n  platform TEXT NOT NULL,\n  message_text TEXT,\n  intent TEXT,\n  confidence FLOAT,\n  entities JSONB,\n  risk_summary JSONB,\n  response_text TEXT,\n  response_sent BOOLEAN DEFAULT false,\n  latency_ms INT,\n  is_known_user BOOLEAN DEFAULT false,\n  created_at TIMESTAMP DEFAULT now()\n);\n\n-- 3. Localization templates\nCREATE TABLE localization (\n  language_code TEXT PRIMARY KEY,\n  greeting TEXT,\n  query_response_template TEXT,\n  help_response_template TEXT,\n  error_response_template TEXT,\n  unknown_intent_template TEXT\n);\n\n-- Insert English templates\nINSERT INTO localization (language_code, greeting, query_response_template, help_response_template, error_response_template, unknown_intent_template) \nVALUES (\n  'en',\n  '👋 Hi! I\\'m the MyPrivacyTOOL scanner. Ask me to check if your data is exposed.',\n  '🔍 Scanning your exposure: {entity}. Found on {broker_count} data brokers. {risk_level}',\n  '📖 {topic_explanation} Learn more: {help_url}',\n  '❌ Sorry, something went wrong. Please try again or contact support.',\n  '❓ I didn\\'t understand that. Try asking: \"Check if my email was leaked?\"'\n);\n\n-- RLS policies for service role\nALTER TABLE user_state ENABLE ROW LEVEL SECURITY;\nALTER TABLE interaction_log ENABLE ROW LEVEL SECURITY;\nALTER TABLE localization ENABLE ROW LEVEL SECURITY;\n\nCREATE POLICY \"allow_service_role\" ON user_state \n  FOR ALL \n  TO \"service_role\" \n  USING (true);\n\nCREATE POLICY \"allow_service_role\" ON interaction_log \n  FOR ALL \n  TO \"service_role\" \n  USING (true);\n\nCREATE POLICY \"allow_service_role\" ON localization \n  FOR ALL \n  TO \"service_role\" \n  USING (true);\n\n-- Create indexes for performance\nCREATE INDEX idx_user_state_platform ON user_state(platform);\nCREATE INDEX idx_interaction_log_sender ON interaction_log(sender_id);\nCREATE INDEX idx_interaction_log_created ON interaction_log(created_at DESC);\n```\n\n### Verify RLS Policies\n\nGo to **Supabase Dashboard → SQL Editor** and run:\n\n```sql\nSELECT * FROM pg_policies WHERE tablename IN ('user_state', 'interaction_log', 'localization');\n```\n\nEach table should have at least one policy.\n\n## Integration with Social Platforms\n\n### X (Twitter) Integration\n\n1. **Register webhook endpoint** in X API settings:\n   ```\n   https://mpt-core-brain.your-account.workers.dev/\n   ```\n\n2. **Set webhook secret** in X Developer Portal → Your App → Settings\n   - Go to **Cloudflare Dashboard → Workers → mpt-core-brain**\n2. Click **Analytics** to view:\n   - Request counts\n   - Error rates\n   - CPU time\n   - Wall-clock time\n\n### Query interaction logs\n\nIn Supabase:\n\n```sql\n-- Average latency by intent\nSELECT intent, AVG(latency_ms) as avg_latency, COUNT(*) as request_count\nFROM interaction_log\nWHERE created_at > NOW() - INTERVAL '7 days'\nGROUP BY intent\nORDER BY avg_latency DESC;\n\n-- Error rate\nSELECT \n  COUNT(*) as total_requests,\n  COUNT(*) FILTER (WHERE response_sent = false) as failed_responses,\n  ROUND(100.0 * COUNT(*) FILTER (WHERE response_sent = false) / COUNT(*), 2) as error_rate_pct\nFROM interaction_log\nWHERE created_at > NOW() - INTERVAL '24 hours';\n\n-- Top intents\nSELECT intent, COUNT(*) as count\nFROM interaction_log\nWHERE created_at > NOW() - INTERVAL '7 days'\nGROUP BY intent\nORDER BY count DESC;\n```\n\n## Troubleshooting\n\n### Issue: 401 Unauthorized\n\n**Cause:** Webhook secret mismatch\n\n**Fix:**\n1. Verify `WEBHOOK_SECRET` in Cloudflare Dashboard matches the secret in the webhook request header\n2. Check constant-time comparison logic in `index.js` (`constantTimeEqual` function)\n\n### Issue: 429 Too Many Requests\n\n**Cause:** Rate limit exceeded\n\n**Fix:**\n1. Check KV is properly configured\n2. Verify rate limit threshold (default: 10 messages/minute)\n3. In `index.js`, modify `isRateLimited()` to adjust threshold if needed\n\n### Issue: Supabase queries fail (500 error)\n\n**Cause:** Wrong API key or RLS policy issue\n\n**Fix:**\n1. Verify `SUPABASE_SERVICE_KEY` is the **service role key**, not anon public key\n2. Check RLS policies are in place and allow service role\n3. In Supabase, run: `SELECT * FROM pg_policies;`\n\n### Issue: Qwen API returns 401\n\n**Cause:** Invalid or expired API key\n\n**Fix:**\n1. Verify `QWEN_API_KEY` in Cloudflare Dashboard\n2. Check API key hasn't expired in Alibaba Cloud console\n3. Verify `QWEN_MODEL` name matches available model\n\n### Issue: Response not sent to user\n\n**Cause:** Response routing failed\n\n**Fix:**\n1. Check `platform` field is either `\"x\"` or `\"telegram\"`\n2. Verify `X_API_KEY` or `TELEGRAM_BOT_TOKEN` is set if routing directly\n3. Check `MIRROR_AND_RISK_WORKER_URL` if delegating to MPC-8302\n\n## Next Steps\n\n1. **Deploy MPC-8301** (Social Platform API Integration) — registers webhook endpoints\n2. **Deploy MPC-8302** (Mirror & Risk Engine) — provides scan + risk summary\n3. **Monitor logs** — watch for errors during first week of traffic\n4. **Tune rate limits** — adjust based on traffic patterns\n5. **A/B test responses** — test different localization templates\n\n## Support\n\nOpen an issue in the repo or Slack message in #myprivacytool-dev for:\n- Deployment questions\n- Performance concerns\n- Integration issues\n- Feature requests\n"
