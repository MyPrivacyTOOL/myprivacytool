# MPC-9813: automated live check of the email confirm gate and the "show us your listing" check

Runs with no human: `.github/workflows/f1-live-check.yml` (after every successful synthetic-Worker deploy on `main`, and on demand) -> `scripts/f1-live-check/run.mjs`.

**How, without bypassing production Turnstile.** The scan goes to `mpt-scan-report-synthetic-f1` (`workers/scan-report/wrangler.synthetic-f1.toml`): the same Worker code as production with Cloudflare's public Turnstile TEST secret, the gate and listing switches ON, no cron, no HubSpot, test-mailbox allowlist. It is separate from `mpt-scan-report-synthetic` because turning the gate on there would make the nightly chain wait for a click it never makes. It writes to the production database; the production cron then sends the report to the same `testingnt69+f1-*` alias. Sent emails are read back from the provider (Resend). The "click" is the real `POST /api/scan/confirm` with a token signed by the synthetic Worker's test-only signing key (`SCAN_REPORT_UNSUBSCRIBE_SECRET`). The listing page is `public/test-fixtures/listing-synthetic.html` (static, `noindex`, `Disallow` in robots.txt, an invented person).

**Steps** (a failing step stops the run; later steps are SKIPPED, never passed): db_ready; scan_request (confirm_required + listing_saved true); stored_and_waiting (marked, details stored against the scan number, no result); confirmation_email (read back from the provider); held_before_click (waits 6.5 min = at least one production cron tick: still pending, 0 attempts, page not read); forged_click_refused (401); click (200, `email_confirmed_at` set); listing_result (Listed / exact / high / not a guess; evidence_url = the page; source free / user_supplied_page; no page text stored); live_view (email-link view returns the Listed result; no key = 401); report_sent (production cron, after the click); report_block (sent report contains "Listings you showed us" / Listed / the link); delete_by_scan_number (the typed details and results go with the scan); cleanup.

**Can not prove:** the real Turnstile widget in a real browser; delivery into a real inbox; how Gmail/Outlook render the emails. If the provider's list/retrieve API is unavailable the confirmation-email content is reported as "not verified" in the summary, never as passed.

**Exit codes:** 0 pass, 1 a step failed, 2 not configured (missing secret). Rollback: delete the Worker `mpt-scan-report-synthetic-f1` and this workflow.
