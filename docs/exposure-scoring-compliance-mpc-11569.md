# Exposure scoring: compliance with the owner's rules (MPC-11569)

Rules: Notion, "MPT > Exposure scoring — the rules for every channel", decided by the owner on 2026-11-27 (https://app.notion.com/p/42628547eaa781ae9159db9fc777aa67). Updated 2026-11-28.

**One engine.** The owner chose one method for every channel. It lives in `shared/exposure/exposure.js` (method `exposure-tier-1`, MPC-11622). Telegram is on it (`channels/telegram.js`); web and email are on it too (`channels/web.js`, `channels/email.js`, scope data generated by `scripts/build-exposure-scope.mjs`). The separate `scoreV3` engine built earlier in MPC-11569 was merged in PR 950 and **retired in the follow-up PR that ports web and email onto the core**; only its data and tests live on. The category-weighted `exposure-v2` was never user-visible (a shadow field in the report JSON only) and must not be flipped.

| Rule | exposure-v1 (ships today) | exposure-v2 (shadow field only) | exposure-tier-1 on the shared core (web, email, Telegram) |
|---|---|---|---|
| 1. Exposure AND "n of N fields returned" side by side | Exposure and a coverage percent (checked / 54) | Same, with 60 | `countText` ("47 of 47 fields returned") beside the score |
| 2. Weight by risk tier (1/2/3), not by category | **No**: nine category weights | **No**: nine plus email 10 | **Yes**: approved catalogue tier per field, no category weight anywhere |
| 2. Fixed denominator, every in-scope data point counts | **No**: divides by what was checked | **No** | **Yes** |
| 3. No effort bonus, "I fixed it" credit, wizard credit, default weight | Complies | Complies | Complies and tested (extra properties are ignored) |
| 4. Nothing returned is never "clear", "protected", "safe", "fixed" | **No** in copy: the report says CHECKED AND CLEAR | **No** | Core supplies the required wording and tests forbid the words; the report copy still has to change before any headline switch |
| 5. Stacked bar: always sent vs your settings | No | No | `bar.base` / `bar.settings` |
| 7. Bands valid for a channel with a floor, or show position in range | **No**: the web floor is 76 under tier weights, so "Low" is unreachable | **No** | `position` (percent of the range you can change); no band is shown |
| 8. At least ten synthetic profiles per channel; monotonic, floor, deterministic; publish the table | No | One fixture | Web 13, email 11, Telegram 12; monotonic incl. all 64 email outcomes; table in `docs/exposure-tier-1-web-email-fixtures.md` |

## Decisions made for web and email (owner may change)

1. **Scope N is observable data points: 47 web + 6 email.** The 7 web hexagons the site can never observe are not in N, as Telegram's 5 never-evaluated fields are not in its 25. The old 54 and 60 stay for badges and counts.
2. **Tiers are the approved catalogue risk tiers (2026-10-28), not the registry's `truth.sensitivity`.** They differ for 29 of the 60 data points.
3. **"Your settings" for web = the nine hexagons with a typed fix block** (approved MPC-8733 model), a vitest keeps the list equal to `FIX_BLOCK_IDS`. Email: Gravatar, Libravatar and public GitHub commits are changeable; the address's name, its provider and its domain record are not. Floors: web **76**, email **40**.
4. **Web: everything that is not `found` is "not returned"** (a web check arrives as `not_checked` whether it found nothing or could not run, and the registry cannot tell which), with one guard: a scan in which nothing produced a result has no score. **Email: a `not_checked` check is NOT observed** (its source was unreachable), so a report with any email check unreachable has no email score; the core never invents a number from a check that did not run.
