HITL confirmation loop

What happens when someone taps a finding and says it is theirs, not theirs, or wrong. Merged in PR 375, on top of the deep-dive endpoints already in main.

One tap, end to end

Browser useHexagonState

Tap: yes, no, or disputeThe tile changes at once. The screen never waits for the server.
POST /api/scan/hexagon-interaction
{ scan_id, hexagon_id, action }action is confirm, reject or dispute. No finding value is sent.
Offline, 403, 5xxSwallowed. The page keeps its own state.

Worker webhook-receiver

Proof of possessionScan must exist, be under 24h old, and belong to a wa_id that messaged us. Otherwise 404.
Transition ruleOnly a guess can be confirmed or rejected. Only a checked finding above 0.8 can be disputed. Anything else is 409.
Save new stateScan state in Firestore, status becomes confirmed, false_positive or disputed.
persistInteractionFail-soft. A database problem never blocks the answer.

Supabase service_role only

mpt_hexagon_interactionsEvery accepted answer: session, hexagon, action, confidence, provider.
reject or dispute, and the finding names a provider
osint_engine_tuning_logrejected writes false_positive_rate. disputed writes dispute_rate. No session, no wa_id.
Learning loopThe OSINT engine reads this log to lower confidence for a provider that keeps being wrong.
