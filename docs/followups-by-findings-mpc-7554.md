## 1. Who gets day-3 and day-7 today, and why (read from the code, then checked against production counts)

`runFollowUpJob` (workers/scan-report/index.js) mails a report's address when ALL of these hold: report sent, 3 days (stage 1) or 7 days (stage 2) have passed since `report_sent_at`, `UNSUBSCRIBE_SECRET` is set, the address is allowed, the user has not opted out, and **`users.cohort_number` is set** (or the allowlist is non-empty, i.e. test mode). `cohort_number` is given by `claim_onboarding_cohort()` to the first 100 users whose report is delivered, and only while the recipient allowlist is empty.

**The "first 100 users only" claim is TRUE in the code today.** Day 3 and day 7 fire on the calendar, not on findings, and the day-3 content comes from the old 8-category mirror (`mirror_report.next_steps`): it can say "Remove your Spokeo listing" although the report never checked Spokeo, and it names nothing the person's own hexagons found.

Production counts, read-only on 2026-10-28 (counts only): 24 reports sent; 23 of those users hold a cohort number; 1 report older than 3 days belongs to a user outside the cohort and gets no follow-up; 16 reports have had both follow-ups, 2 have had day 3 only; 5 users have opted out. At 100 users the other users would get nothing.

## 2. What this change does (all of it only with `FOLLOWUP_STATE_ENABLED = "true"`)

| | |
|---|---|
| Who | **Every user**, not a cohort. The cohort number only decides whether the "first 100" sentence appears. |
| State per report (computed, `lib/followup.js`) | **findings** (at least one hexagon FOUND: saved web scan re-checked against the registry, or an email check) · **nothing_found** · **fixed** (`scans.fixed_at`) · **unsubscribed** (THE opt-out: users flag or suppression record). unsubscribed beats fixed beats findings. |
| Day 3, findings | Names the user's **top 3** findings (risk hexagons before informational ones, email findings first), each with the one next step and a tagged guide link; says how many more are in the report. |
| Day 3, nothing found | A different, shorter email: nothing needs fixing, and nothing found is not the same as safe (NOT CHECKED means we could not look). No fix steps. |
| Day 7 | Asks for feedback in both live states. |
| Upsell | **None, in any state.** There is no paid-plan sentence in any variant, and a test fails if one appears. |
| "I have fixed this" | A signed link per report in the day-3, day-7 and report emails. GET only shows a confirm page (mail scanners open links); the button POSTs `scans.fixed_at` and ends the follow-ups for that report. It is **not an unsubscribe**: no opt-out flag, no suppression record, and the person can still request and receive a new report. |
| Ended states leave the queue | A fixed or unsubscribed report is ended on the row (`followup_stage = 2`, `followup_ended`) instead of being re-read every run. |
| Rules unchanged and re-tested | Unsubscribe (signed link, suppression-only, users flag), cancel-if-unsubscribed, recipient allowlist, `UNSUBSCRIBE_SECRET` gate, one send per stage. |
| Size | Each email is well under 100 KB and passes the markup and plain-text parity checks (`lib/renderChecks.js`). |
